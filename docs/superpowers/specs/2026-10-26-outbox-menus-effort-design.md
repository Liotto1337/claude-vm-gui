# Файлы Claude в ленте, меню с локальным выбором, effort за кнопкой — дизайн

Windows-клиент `claude-vm-gui` (0.5.1 → 0.6.0) и Android-форк `claude-vm-gui-android` (0.3.1 → 0.4.0). Три независимые части одного выпуска. Всё, что здесь не сказано, остаётся как сейчас.

Правила пользователя: дизайн не менять (новое — из существующих компонентов, цветов и шрифтов); в релиз — только после ревьюера; неясное — спрашивать. Windows — релиз, Android — pre-release до проверки на телефоне.

## Часть 1. Файлы Claude в ленте (папка «для вас»)

### Цель

Запрос пользователя (2026-10-26): файлы, которые Claude делает для пользователя (картинки и скриншоты, HTML-страницы и отчёты, текст и код, любые файлы — APK, .exe, PDF, архивы), получать прямо в GUI, а не публикацией на claude.ai.

### Решения, принятые с пользователем

| Вопрос | Решение |
|---|---|
| Какие файлы | Все четыре вида: картинки, HTML, текст и код, любые на скачивание |
| Как GUI узнаёт файл | Папка «для вас» `~/.cache/claude-vm-gui/outbox`: Claude кладёт файл туда и называет путь в ответе |
| HTML | Открывается в браузере по умолчанию (ПК и телефон) |
| Очистка | Файлы старше 7 дней удаляются (как загрузки) |

### Договорённость с Claude

В `/root/.claude/CLAUDE.md` на ВМ (глобальные инструкции пользователя) — раздел «Файлы для пользователя»: файлы для пользователя не публиковать на claude.ai (Artifact) и не отдавать ссылкой, а сохранять в `~/.cache/claude-vm-gui/outbox/` (можно во вложенную папку) и называть полный путь в ответе. HTML — одним файлом, стили и скрипты внутри. Путь пишется абсолютным (`/root/.cache/claude-vm-gui/outbox/…`).

### Сервер

- Папку создаёт GUI при подключении (`mkdir -p`, `realpath`), как папку загрузок; тот же сервис, что загрузки, получает вторую разрешённую папку.
- Очистка: `find … -type f -mtime +7 -delete` вместе с очисткой загрузок.
- Чтение — только внутри outbox: путь проверяется после `realpath -e` (никаких `..` и ссылок наружу), иначе `BAD_PATH`. Нет файла — `NOT_FOUND` («Файл удалён с ВМ»).

### Разбор журнала

- В тексте ответа Claude (блоки `text` записи `assistant` основной ветки) ищутся абсолютные пути, содержащие `/.cache/claude-vm-gui/outbox/`. Граница пути — пробел, перевод строки, обратная кавычка, кавычки, `)`/`]`/`>`, конечные `.,:;!?` отбрасываются; markdown-ссылка `[текст](путь)` даёт путь.
- Элемент ленты ответа получает поле `files: string[]` (уникальные пути в порядке появления). Текст ответа не меняется.

### Лента

Под ответом — карточка на каждый файл (существующий `FileView`, расширенный):

- **Картинка** (`isImageName`) — превью по ширине, нажатие — на весь экран (`Lightbox`); больше 50 МБ — как «любой файл».
- **Текст и код** (`isTextName` или первые байты не двоичные) — раскрывающийся просмотр начала файла, как у загрузок.
- **HTML** (`.html`, `.htm`) — кнопка «Открыть в браузере».
- **Любой файл** (и все виды выше) — имя, размер, кнопка «Сохранить».
- Файла нет — «Файл удалён с ВМ»; ошибка чтения — текст ошибки.

#### Windows

- «Открыть в браузере»: файл скачивается по SFTP во временную папку приложения (`app.getPath('temp')/claude-vm-gui/<случайное>/<имя>`) и открывается `shell.openPath`. Временная папка чистится при выходе.
- «Сохранить»: диалог «Сохранить как» (`dialog.showSaveDialog`, имя по умолчанию — имя файла, папка — «Загрузки»), потоковое скачивание по SFTP с прогрессом на карточке («Сохранено» с кнопкой «Показать в папке» — `shell.showItemInFolder`). Отмена диалога — ничего.
- Скачивание — в main (байты не идут через IPC), путь проверяется тем же правилом outbox.

#### Android

- SSH живёт в Kotlin (`VmBridgePlugin`), поэтому скачивание — новым методом моста: поток SFTP прямо в файл, без передачи байтов в WebView.
- «Сохранить» → «Загрузки»: Android 10+ — `MediaStore.Downloads` без разрешений; Android 8–9 (`minSdk` проекта — 26) — публичная папка Download с разрешением `WRITE_EXTERNAL_STORAGE` (`maxSdkVersion="28"`, запрос при первом сохранении; отказ — ошибка на карточке). Прогресс на карточке; «Сохранено» — кнопка «Открыть» (`ACTION_VIEW` по URI файла).
- «Открыть в браузере» → файл в кэш приложения и `ACTION_VIEW` через существующий `FileProvider` (`${applicationId}.fileprovider`, добавить путь кэша) с типом `text/html` (выбор приложения, обычно Chrome).
- Проверка пути outbox — до скачивания (`realpath` через exec), как в `UploadService.read`.

### Ошибки и края

- Нет подключения — кнопки неактивны, подсказка «Нет подключения к ВМ».
- Обрыв на середине скачивания — недокачанный файл удаляется, на карточке ошибка и «Повторить».
- Путь в ответе указывает на папку, а не файл — карточки нет.
- Повтор одного пути в ответе — одна карточка.

## Часть 2. Меню: выбор собирается локально

### Цель

Запрос пользователя: в карточке меню (радиокнопки, чекбоксы) каждое нажатие уходит в Claude Code и отображается с задержкой. Клиент должен собирать ответ сам и отправлять только по Enter.

### Поведение

- Нажатие на вариант, ↑↓, пробел, цифры меняют только карточку (мгновенно): курсор, отмеченная радиокнопка, галочки. В Claude Code ничего не уходит.
- **Один выбор (радиокнопки):** кнопка «Ответить» (как «Готово») и Enter отправляют «перейти к выбранному варианту + Enter» (или цифру, если у варианта есть номер). Радиокнопка больше не отвечает с первого нажатия.
- **Несколько (чекбоксы):** «Готово» и Enter отправляют: для каждого варианта, чьё желаемое состояние отличается от экрана, — перемещение к нему от текущей позиции курсора и пробел; затем перемещение к «Submit» и Enter. Последовательность считается чистой функцией от разобранного меню и желаемого выбора (`answerKeysFor`).
- **Свой ответ:** поле «Свой ответ…» заполняется локально; при отправке — перемещение к варианту, текст (`chat.typeText`), для одного выбора — Enter, для нескольких — вариант считается отмеченным.
- **Несколько вопросов** (вкладки): Claude Code показывает вопросы по одному — ответ собирается и отправляется на каждый вопрос отдельно. ←→ и Tab по-прежнему уходят сразу (переключают вопрос).
- **Esc** и effort в `/model` (◀ ▶) уходят сразу, как сейчас.
- Пока ответ уходит — варианты и кнопки неактивны, «отправляю…». Если через 3 с на экране то же меню (тот же заголовок и варианты), локальный выбор заменяется состоянием с экрана и показывается ошибка «Claude Code не принял ответ — проверьте выбор».
- Пришло другое меню (сменился заголовок, варианты или вопрос) — локальный выбор сбрасывается к состоянию экрана.

### Отправка пачкой

Клавиши уходят последовательно без ожидания перерисовки. Проверить на настоящем Claude Code 2.1.310 на ВМ, что пачка не теряется (меню с 4+ вариантами, чекбоксы через один, Submit). Если теряется — пауза между клавишами (подобрать, не больше 50 мс), всё равно одним действием.

## Часть 3. Effort за кнопкой с делениями

- Вместо открытого ползунка у поля ввода — кнопка в стиле «Модель» (`choice-btn`): на ней текущий уровень («high»), неизвестный — «Effort». `title` — «Effort · отправит /effort», `aria-label` — «Effort: high» / «Effort».
- Первое нажатие открывает всплывающую панель над кнопкой (как меню «Модель»): ползунок с делением на каждом уровне, над каждым делением подпись уровня (из модели, иначе `low medium high xhigh max`), текущий — выделен.
- Выбор: бегунок и стрелки — как сейчас (`/effort` по отпусканию; со стрелками — после паузы 600 мс одной командой); нажатие на подпись или деление — сразу этот уровень. Кнопка сразу показывает новый уровень. Панель после выбора остаётся открытой.
- Закрытие: второе нажатие на кнопку, Esc, нажатие вне панели.
- Телефон: панель по ширине поля ввода, деления и подписи — в зоне касания 48 px.

## Что где меняется

Общий renderer и shared совпадают на двух платформах.

- `src/shared/transcript-parse.ts`: `files` у ответа Claude (`outboxPaths(text)` в `src/shared/upload-name.ts` рядом с `UPLOAD_DIR_MARK`).
- `src/main/upload.ts` / `src/core/upload.ts`: outbox — создание, чтение с проверкой, очистка 7 дней; Windows — `download(path, dest)` потоком, `openHtml(path)`.
- IPC (Windows): `outbox:save`, `outbox:open`, событие прогресса; Android: методы моста `downloadFile`, `openFile` (Kotlin, `FileProvider`, `MediaStore`).
- Renderer: `FileView` — карточки файлов ответа; `ChatItem` ответа — `files`.
- `src/shared/screen-parse.ts`: `answerKeysFor(menu, choice)`; `MenuCard.tsx` — локальный выбор, «Ответить», «отправляю…».
- `EffortSlider.tsx` → `EffortButton` (кнопка + панель с делениями); `Composer.tsx`.
- `/root/.claude/CLAUDE.md` на ВМ — раздел «Файлы для пользователя».

## Проверка

- Модульные: `outboxPaths` (пробелы, кавычки, markdown-ссылка, пунктуация в конце, повтор, чужая папка); `files` у ответа; `answerKeysFor` (радио с номером и без, чекбоксы — включить/выключить/без изменений, курсор не на первом, Submit, свой ответ); проверка пути outbox (`..`, ссылка наружу).
- Интеграционные (sshd ВМ): outbox создаётся, чтение вне папки — `BAD_PATH`, скачивание потоком, очистка.
- E2E Windows: ответ с путём к картинке, HTML и `.zip` в outbox → превью, «Открыть в браузере» (перехват `shell.openPath`), «Сохранить» (подмена диалога) → файл совпадает; меню: клики не шлют клавиш, «Готово» шлёт одну пачку, итог на экране фейка совпадает; effort: кнопка показывает уровень, панель открывается и закрывается вторым нажатием, подпись выбирает уровень.
- E2E Android (Chromium + мост разработки): карточки и вызовы моста; Kotlin — JUnit/Robolectric для скачивания в MediaStore и `FileProvider`.
- Настоящий Claude Code на ВМ: пачка клавиш меню (вопрос с чекбоксами через AskUserQuestion) и файл в outbox от Claude.
- Перед релизом — ревьюер всей ветки.
