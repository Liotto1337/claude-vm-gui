# Контекст сессии и «Сжать сессию» — дизайн

Windows-клиент `claude-vm-gui` (0.4.0 → 0.5.0) и Android-форк `claude-vm-gui-android` (0.2.1 → 0.3.0). Всё, что здесь не сказано, остаётся как сейчас.

## Цель

Запрос пользователя (2026-10-24): метрики контекста открытой сессии (сколько занято, из чего, сколько до автосжатия) и принудительное сжатие сессии для экономии токенов. Образец — панель «Контекст» со скрина: «Использовано: 83 %  832,3k / 1M», категории с цветом, токенами и процентом, «Токенов до автосжатия», кнопка «Сжать сессию».

Правила пользователя: дизайн не менять (панель — из существующих цветов, полосок и шрифтов блока «Расход»); в релиз — только после ревьюера; неясное — спрашивать.

### Решения, принятые с пользователем

| Вопрос | Решение |
|---|---|
| Источник цифр | Гибрид: «занято» — постоянно по журналу; разбивка — из `/context`, который GUI сам отправляет при открытии панели, если Claude не работает |
| Место | Шапка сессии: значок «Контекст N %», по нажатию — выпадающая панель (Android — нижний лист) |
| Кнопка сжатия | Диалог подтверждения с необязательным полем «Что сохранить в сводке» → `/compact [текст]` |

## Источники данных

### «Занято» — по журналу

Последняя запись `type: "assistant"` основной ветки (не `isSidechain`) с `message.usage`: `input_tokens + cache_read_input_tokens + cache_creation_input_tokens`. Модель — `message.model`. Пересчитывается при каждом новом ответе тем же разбором журнала, что строит ленту (`ParseState`). Записи синтетической модели `<synthetic>` пропускаются. После `/compact` первая запись с `isCompactSummary` обнуляет «занято» до следующего ответа (значение неизвестно → показывается «—»).

### Разбивка — вывод `/context` в журнале

Claude Code 2.1.310 пишет вывод `/context` в журнал целиком: запись `type: "system", subtype: "local_command"`, `content` = `<local-command-stdout>…</local-command-stdout>` с ANSI-цветами. Перед ней — запись пользователя с `<command-name>/context</command-name>`. Разбор (без ANSI):

- `29.7k/1m tokens (3%)` → занято на момент замера и размер окна (`k` = 1e3, `m` = 1e6, регистр не важен);
- строки категорий `⛁ <Имя>: <N>k tokens (<P>%)`, включая `Free space: 937.4k (93.7%)` (без слова tokens) и `Autocompact buffer: 33k tokens (3.3%)`;
- цвет категории — ANSI-код перед значком `⛁`/`⛀`/`⛶`/`⛝` в этой строке (30–37, 90–97 → цвет палитры терминала из текущей темы; `2m` — приглушённый);
- `Auto-compact window: …` не нужен (окно уже известно из итоговой строки).

Замер хранится в состоянии сессии вместе со временем записи (`timestamp`). Неразобранный вывод (другой формат) — разбивки нет, панель показывает только «занято» и пометку «Разбивка недоступна».

### Размер окна и буфер, когда `/context` ещё не было

Последний замер `/context` с той же моделью (по `message.model`) запоминается в клиенте (Windows — `localStorage`, Android — то же хранилище WebView) как `{окно, буфер}`. Нет и его — процент не показывается, значок «Контекст 29.7k», панель без полоски процента.

### Производные величины

- Использовано, % = занято / окно, округление до целого в значке, до 0,1 в строках.
- Токенов до автосжатия = окно − буфер − занято, не меньше 0.
- «Messages» и «Free space» в разбивке берутся из замера как есть; итог «занято» в шапке панели — из журнала (свежее замера).

## Интерфейс

### Значок в шапке сессии

Перед переключателем «Лента | Терминал» (effort живёт в поле ввода): «Контекст 83 %» (или «Контекст 29.7k» без окна, «Контекст —» до первого ответа). Цвет текста обычный; ≥ 80 % — цвет предупреждения темы; ≤ 5 % окна до автосжатия — цвет ошибки темы. Видим в режимах «Чат» и «Терминал». Сессия без журнала (не Claude) — значка нет.

### Панель «Контекст»

Выпадает под значком (Windows) / нижний лист (Android), закрывается кликом вне, Esc, повторным нажатием. Сверху вниз:

1. Заголовок «Контекст».
2. «Использовано: 83 %» слева, «832.3k / 1M» справа; под ними полоска: заполнение по категориям их цветами (как на скрине), без разбивки — одним цветом акцента.
3. Категории в порядке вывода `/context`: квадратик цвета, имя (как в Claude Code, по-английски), токены, процент. Строка «Free space» — последней перед «Autocompact buffer».
4. Пометка времени замера «Разбивка на 14:32», если замер не из текущего открытия панели; «Разбивка недоступна», если её нет.
5. Низ: «Токенов до автосжатия: 134,7k» и кнопка «Сжать сессию».

Числа — «832.3k», «1M» (`formatTokens`); «Сегодня: N токенов» в «Расходе» переводится на тот же формат.

### Автозапуск `/context`

При открытии панели, если сессия не занята (`busy` = false, на экране приглашение Claude без статуса и с пустым полем ввода), GUI отправляет в сессию `/context` + Enter через ту же проверку `target(expected)`, что и обычный ввод. Не чаще раза в 10 с на сессию. Пока ждём новую запись — у пометки времени «обновляю…». Занята — не отправляем, показываем прошлый замер.

### «Сжать сессию»

Неактивна, пока сессия занята (подсказка «Дождитесь окончания ответа»). Нажатие → диалог (существующий `ConfirmDialog` / его Android-аналог):

- заголовок «Сжать сессию?»;
- текст «История для Claude заменится краткой сводкой. Само сжатие тоже тратит токены.»;
- необязательное поле «Что сохранить в сводке»;
- кнопки «Сжать» и «Отмена».

«Сжать» → `/compact` или `/compact <текст>` (переводы строк в тексте заменяются пробелами) + Enter, через `target(expected)`. Панель закрывается.

### Лента

- Пара «`/context` + её вывод» в ленте не показывается (ни отправленная GUI, ни набранная вручную): данные живут в панели. В терминале вывод остаётся.
- `/compact` показывается как сейчас (строка пользователя), сводка сжатия по-прежнему скрыта.

## Что где меняется

Общий код совпадает на двух платформах (как `usage.ts` в 0.4).

- `src/shared/context-parse.ts` (новый): `parseContextOutput(text) → ContextSnapshot | null`, `usedFromAssistant(entry) → { used, model } | null`.
- `src/shared/transcript-parse.ts`: в `ParseState` — `context: { used, model, snapshot, snapshotAt }`; `/context` и его вывод → `'skip'` + замер в состояние.
- Событие ленты (`items`) дополняется полем `context` (Windows — IPC из `TranscriptService`, Android — тем же путём из `core`).
- Renderer: `ContextBadge`, `ContextPanel`, `CompactDialog` (на базе `ConfirmDialog`); `SessionHeader` — значок. Android: те же компоненты, панель — в нижнем листе по образцу листа сессии.
- Отправка: существующий путь `send(session, text)`; новых IPC для `/context` и `/compact` не нужно.

## Ошибки и края

- Нет подключения / сессия закрыта — значок «Контекст —», кнопка неактивна.
- Модель сменили (`/model`) — окно берётся по новой модели; старый замер разбивки помечается временем и остаётся до нового.
- `/context` не пришёл за 15 с — снимаем «обновляю…», остаётся прошлый замер.
- Очень старый журнал без `usage` — «Контекст —».

## Проверка

- Модульные: разбор настоящего вывода 2.1.310 с ANSI (фикстура), форматы `k`/`m`/без суффикса, неизвестный формат → null; «занято» по последней записи, пропуск sidechain и `<synthetic>`, сброс после сжатия; скрытие `/context` из ленты; производные величины и пороги цвета; запоминание окна по модели.
- Компоненты: значок (три вида), панель с разбивкой и без, неактивная кнопка при `busy`, диалог формирует `/compact <текст>`.
- E2E (обе платформы, Claude Code на ВМ): открытие панели отправляет `/context` в нужную сессию и показывает категории; «Сжать» → `/compact` уходит в нужную сессию; лента не содержит вывода `/context`.
- Перед релизом — ревьюер всей ветки. Windows — релиз; Android — pre-release до проверки на телефоне.
