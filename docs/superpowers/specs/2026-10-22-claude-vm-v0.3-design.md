# Claude VM 0.3 (Windows) и 0.2 (Android) — дизайн

Доработка двух приложений: Windows-клиента `claude-vm-gui` (здесь, 0.2.2 → 0.3.0) и Android-форка `claude-vm-gui-android` (0.1.1 → 0.2.0). Всё, что здесь не сказано, остаётся как сейчас.

## Цель

Двенадцать изменений по ТЗ пользователя (2026-10-22):

1. Проверка обновлений по GitHub; если версия не последняя — баннер «Доступно обновление» с крестиком, яркого цвета из темы.
2. Строка сессии выше: хвосты букв (q, у, р) обрезаются снизу.
3. В ленте не показывать огромное сообщение (сводку сжатия контекста).
4. Многострочная вставка: `<pasted_content id="…">` дублируется и висит внизу ленты.
5. Меню Claude Code (всё, что выбирается стрелками) — в ленте; один вариант — радиокнопки, несколько — чекбоксы.
6. Android: текст из поля ввода исчезает сразу при отправке.
7. Вложения любых файлов, не только картинок; заметка памяти на ВМ о папке загрузок — про любые файлы.
8. Android: «Отслеживать» для сессий; уведомления только от отслеживаемых.
9. Содержимое вложений в ленте: картинка целиком, текст раскрывается.
10. Размер окна tmux — под устройство, которым пользуются.
11. Windows: в режиме «Терминал» поле ввода скрыто.
12. Windows: текст из поля ввода исчезает сразу при отправке (как п. 6).

Правила ТЗ: дизайн не менять; в релиз — только после проверки ревьюером; неясное — спрашивать.

### Решения, принятые с пользователем

| Вопрос | Решение |

| Меню | В ленте последним элементом; после ответа остаётся строка «Вопрос → выбрано: …» |

## 1. Баннер «Доступно обновление»

- **Источник.** `GET https://api.github.com/repos/Liotto1337/<репозиторий>/releases/latest` без токена (оба репозитория открытые; лимит 60 запросов в час с адреса — хватает). Берутся `tag_name` и `html_url`.
- **Когда.** Через 5 с после запуска и раз в 6 часов, пока приложение открыто (Android — только пока на экране).
- **Сравнение.** `tag_name` без `v` и версия приложения сравниваются как три числа (`newerVersion(a, b)` в `src/shared/version.ts`); черновики и пререлизы GitHub в `latest` не попадают. Неразборчивая версия — баннера нет.
- **Где сеть.** Windows — в main-процессе (`net.fetch`), в рендерер приходит событие `update:available { version, url }` — CSP окна не трогается. Android — `fetch` из WebView (api.github.com отдаёт CORS-заголовки) в `src/core`.
- **Вид.** Полоса вверху основной области (над шапкой сессии, на всю ширину `main-column`): «Доступно обновление 0.3.1» и кнопка ✕ (`aria-label="Закрыть"`). Фон — существующий акцентный токен темы (глина, `--accent`, `#d97757` в обеих темах), текст тёмный `#141413` (контраст около 6:1; белый на глине — около 3:1, мало), шрифт 600. Других новых цветов нет. Отступы, скругление и размер шрифта — как у существующей плашки `.banner`.
- **Нажатие** на полосу (кроме ✕) — `openExternal(html_url)` (только https-ссылка `github.com/Liotto1337/…`, проверка через `externalUrl`).
- **✕** — версия запоминается (`prefs`/config `dismissedUpdate`); баннер для неё больше не показывается, для следующей — снова.
- **Ошибки сети, 403/404, неверный JSON** — молча, следующая попытка по расписанию.

## 2. Строка сессии

Хвосты букв обрезаются из‑за высоты строки текста имени в фиксированной строке списка. Высота строки сессии `ROW_HEIGHTS.session` увеличивается (52 → 56) и у `.session-name`/`.session-cwd` задаётся `line-height`, при котором выносные элементы помещаются. Пагинация считает от `ROW_HEIGHTS`, поэтому согласована автоматически. Шрифты, цвета и отступы — прежние.

Тест (E2E): имя с `qypдру` в строке сессии — `scrollHeight` элемента имени не больше `clientHeight`, а нижняя граница текста не ниже нижней границы строки.

## 3. Сводка сжатия контекста

Запись журнала `type: "user"` с `isCompactSummary: true` (Claude Code пишет её при `/compact` и автосжатии; текст «This session is being continued…», 10–20 тысяч символов) в ленту не попадает. Остальные записи с `isVisibleInTranscriptOnly` — тоже. Тест на `parseTranscriptLines` со строкой в настоящем формате.

## 4. `pasted_content`

Приложение отправляет текст через bracketed paste; Claude Code 2.1.30x записывает многострочную вставку в журнал обёрнутой: `<pasted_content id="c111">\n…\n</pasted_content id="c111">` (бывает и без `id`). Отсюда две ошибки: в ленте видны теги, и временный пузырь отправки не узнаёт своё сообщение (`claimPending` сравнивает текст) и остаётся внизу.

Исправление — в разборе: `unwrapPasted(text)` в `transcript-parse.ts` заменяет каждую пару открывающего и закрывающего тега (с `id` или без) на содержимое без обрамляющих переводов строк. Пузырь после этого совпадает по тексту. Тесты: разбор строки журнала с обёрткой (с `id` и без, несколько вставок в одном сообщении, текст до и после); `claimPending` забирает пузырь отправленного многострочного текста.

## 5. Меню Claude Code в ленте

Сейчас: `parseMenu` → `ParsedMenu` → `MenuCard` над полем ввода, варианты с номерами.

**Место.** Открытое меню — последний элемент ленты (`ChatView`), под последним сообщением, с автопрокруткой к нему. `MenuCard` над полем ввода убирается; поле ввода, пока меню открыто, неактивно, как сейчас. Если лента не видна (режим «Терминал»), меню не показывается — работа в терминале.

**Вид.** Карточка в прежнем стиле (`.menu-card`: заголовок, контекст), варианты:
- **Один выбор** — радиокнопки (`role="radiogroup"`, `role="radio"`, `aria-checked` = вариант под курсором Claude Code). Нажатие на вариант — `menuKeysFor` (стрелки до варианта + Enter), как сейчас.
- **Множественный выбор** (вопрос AskUserQuestion с `multiSelect`; на экране варианты с `☐`/`☒` или `[ ]`/`[✓]`) — чекбоксы (`role="checkbox"`, `aria-checked` — по отметке на экране). Нажатие — стрелки до варианта + клавиша отметки; «Готово» — переход к пункту отправки и Enter.
- **Несколько вопросов** (вкладки вверху экрана AskUserQuestion: `☐ Цвет  ☐ Размер  ✔ Submit`) — подпись «Вопрос N из M» и заголовок текущего вопроса.
- **Свой ответ** («Type something.» и подобные) — поле ввода внутри карточки; Enter в нём — переход к варианту, ввод текста, Enter.
- **Дополнительная ось** (`/model`: effort `◀ … ▶` стрелками ←→) — кнопки ◀ ▶ рядом с подписью значения.
- Клавиши при фокусе на карточке — как сейчас: ↑↓←→ Enter Esc Tab цифры уходят в claude; пробел — тоже (отметка чекбокса).

Точные экраны и клавиши (отметка в множественном выборе, переход к Submit, вкладки вопросов, `/model`) снимаются с настоящего Claude Code 2.1.308 (`scripts/dev/capture-screen.sh`, фейковый Messages API — без запросов к модели) в фикстуры `tests/fixtures/screens/*.ans` до кода разбора. Разбор расширяет `ParsedMenu`: `kind: 'single' | 'multi'`, у варианта `checked?: boolean`, `input?: boolean` (свой ответ), `tabs?: { labels: string[]; current: number }`, `axis?: { label: string; value: string }`. Нераспознанное меню — как сейчас (карточка с тем, что распознано, клавиши работают).

**История.** Когда меню закрылось, в ленту добавляется строка-итог (`kind: 'note'`, стиль существующих заметок) на место карточки:
- «<заголовок> → выбрано: <вариант>» (несколько — через запятую);
- «<заголовок> → отменено», если последней нажата Esc в приложении или экран сменился с меню на поле ввода без выбора.

Итог определяется по последнему экрану с меню (вариант под курсором, отмеченные чекбоксы) и последней клавише, отправленной приложением; поэтому записывается и при ответе в терминале или на другом устройстве (там — по курсору). Хранится в состоянии ленты сессии вместе с якорем — id последнего элемента журнала перед меню, — и в `prefs` (до 50 последних на сессию), чтобы пережить перезапуск. Для AskUserQuestion и разрешений инструментов итог тоже пишется, хотя ответ виден и в результате инструмента — строка короче и стоит на месте карточки.

## 6/12. Поле ввода очищается сразу

`Composer.send`: текст и вложения убираются из поля в момент отправки, до ответа `term.send`; пузырь «отправляется» появляется сразу (как сейчас). Пока идёт отправка, можно набирать следующее, но кнопка отправки неактивна (`sending`). Ошибка отправки: пузырь убирается, показывается ошибка, текст и вложения возвращаются в поле; если поле уже не пустое — неотправленный текст ставится перед новым через пустую строку, вложения добавляются к текущим. Вложения не освобождаются (`revokeObjectURL`) до успешной отправки.

Тесты: E2E — после нажатия «Отправить» поле пустое раньше, чем фейковый claude принял сообщение (задержка приёма в фикстуре); ошибка отправки возвращает текст; новый текст при ошибке не теряется.

## 7. Вложения любых файлов

- **Выбор.** 📎 без `accept` (любые файлы; на Android — системный выбор файлов, галерея и камера в нём остаются), перетаскивание любых файлов, Ctrl+V — файлы из буфера, если их отдаёт система (`clipboardData.files`).
- **Предел** — 50 МБ на файл (`MAX_FILE_BYTES`), иначе «Файл больше 50 МБ». Картинки — тот же предел.
- **Имя на ВМ.** `ГГГГММДД-ЧЧММСС-xxxxxx-<имя>`: `<имя>` — исходное имя файла, в котором всё, кроме букв (любого алфавита), цифр, `.`, `-`, `_`, заменено на `_`, длина до 80 символов, расширение сохраняется; пустое — `file`. Пробелов в пути нет — разбор журнала режет по пробелам. Папка та же: `~/.cache/claude-vm-gui/uploads/`, права 0600, чистка старше 7 дней — как сейчас.
- **API.** `upload.image(id, bytes, ext)` заменяется на `upload.file(id, bytes, name)`; прогресс — как сейчас. В сообщение уходят пути, как сейчас у картинок.
- **Значок в поле ввода** (`AttachmentChip`): картинка — миниатюра, как сейчас; другой файл — значок документа и имя (обрезка с многоточием), прогресс тот же.
- **Память на ВМ.** Заметка `/root/.claude/projects/-root/memory/user-uploads-dir.md` (и строка в её `MEMORY.md`): в папке любые файлы, которые присылает пользователь, имена `ГГГГММДД-ЧЧММСС-xxxxxx-<исходное имя>` (старые — без исходного имени).

## 9. Содержимое вложений в ленте

- **Разбор.** `stripUploads` возвращает не счётчик, а список путей: `ChatItem` `user` получает `files: string[]` (пути из `uploads/`, в порядке появления) вместо `images: number`; `[Image #N]` из Claude Code — как раньше, считаются отдельно (`images`). Слово считается вложением, если содержит `/claude-vm-gui/uploads/` и после последнего `/` — имя файла нового или старого формата. `claimPending` сравнивает число файлов.
- **Чтение с ВМ.** Новый метод `upload.read(path, maxBytes)` → `{ bytes, size, truncated }` или ошибка `NOT_FOUND`. Путь должен лежать в папке загрузок (проверка на стороне сервиса: каноничный путь начинается с каталога загрузок, без `..`). Windows — SFTP `createReadStream` с ограничением; Android — exec `head -c` + `stat` через `SshTransport` (base64 не нужен: канал двоичный). Кэш в рендерере по пути (картинки — `blob:` URL), не больше 50 МБ суммарно, вытеснение старых.
- **Картинка** (`png|jpe?g|gif|webp`) — `<img>` по ширине пузыря (не больше 100 %, высота до 360 px, `object-fit: contain`), пока грузится — заглушка той же высоты. Нажатие — просмотр на весь экран (оверлей, фон затемнён, Esc/«Назад»/нажатие на фон закрывают; на телефоне — через `useBack`).
- **Текстовый файл** — по расширению из списка (`txt md json yaml yml toml ini csv tsv log xml html css js jsx ts tsx py rb go rs java kt c h cpp hpp cs sh bash zsh ps1 sql env conf cfg`, а также файл без расширения) и проверке первых 8 КБ на отсутствие нулевых байтов. Строка «имя · размер» в стиле строки инструмента; нажатие раскрывает содержимое моноширинным блоком (как результат инструмента), до 256 КБ; больше — «показано 256 КБ из N».
- **Остальные** — строка «имя · размер» без раскрытия.
- **Файла нет** (удалён через 7 дней) — «имя · файл удалён с ВМ».
- Имя показывается без префикса даты и случайной части; у старых файлов без исходного имени — как есть.

## 10. Размер tmux по активному устройству

Сервер tmux уже в режиме `window-size latest`: размер окна — по клиенту с последней активностью. Проверено (tmux 3.2a, два клиента 200×50 и 80×30): клиент становится последним активным, если послать в его терминал последовательность «фокус получен» `ESC [ I` — окно сразу принимает его размер, а программа в панели её не получает (при выключенном `focus-events`); `refresh-client` не помогает; изменение размера PTY помогает только при реальной смене размера. `resize-window` не используется: он навсегда переводит окно в ручной размер.

Поэтому `TerminalService` получает метод `activate()` — запись `\x1b[I` в канал `tmux attach` текущей сессии. Вызывается:
- после подключения к сессии (`open`) и переподключения;
- Windows: окно приложения получило фокус (`BrowserWindow` `focus`) и снова показано после сворачивания;
- Android: приложение вернулось на экран (`platform.onVisibility(true)`).

Не чаще раза в 500 мс. Если открыто меню Claude Code, запись разрешена (это не ввод). Интеграционный тест: два клиента разного размера к одному tmux, `activate()` первого — `window_width` = его ширине.

## 11. Windows: поле ввода в режиме «Терминал»

`MainView`: `Composer` показывается только в режиме «Лента». В режиме «Терминал» терминал занимает всю высоту и получает фокус. Переключение обратно на ленту возвращает поле ввода с прежним текстом и вложениями (черновик хранится в состоянии сессии, а не только в компоненте). Только в Windows-репозитории.

## 8. Android: «Отслеживать»

- **Хранение.** Множество имён отслеживаемых сессий для каждой ВМ — в раскладке сайдбара (`Layout.watched: string[]`, `src/shared/layout.ts`), сохраняется вместе с ней в `prefs`; `reconcile` выкидывает имена сессий, которых больше нет. По умолчанию пусто.
- **Интерфейс.** В меню сессии (долгое нажатие и ПКМ) — пункт «Отслеживать» / «Не отслеживать». В строке отслеживаемой сессии — значок колокольчика (SVG в стиле значка булавки, тот же цвет и размер). В настройках под переключателем «Уведомления» — подпись «Только от сессий, отмеченных „Отслеживать“».
- **Нативная часть.** `Background` (`SshHub`) получает `watched: Set<String>`; `setBackground` передаёт список вместе с прочими настройками при каждом изменении. `SessionNotifier` уведомляет только о сессиях из списка; опрос по‑прежнему одной командой, но только по отслеживаемым сессиям (если список пуст — опроса нет). Уведомление о сессии, которую перестали отслеживать, снимается.
- **Тесты.** JUnit: `SessionNotifier` молчит о неотслеживаемой сессии и уведомляет об отслеживаемой; Vitest: `reconcile` чистит `watched`, пункт меню переключает; дымовой тест на эмуляторе: отслеживаемая сессия даёт уведомление «ждёт ответа», неотслеживаемая — нет.

## Проверка

- Каждое изменение — сначала падающий тест (Vitest, Playwright E2E, интеграционные против sshd/tmux на ВМ, JUnit/Robolectric, дымовой тест на эмуляторе для Android), затем код.
- Полные наборы обоих репозиториев зелёные; известная нестабильность composer E2E (опрос списка раз в 5 с против таймаута 5 с) — по возможности чинится попутно в п. 6/12, раз тесты composer всё равно меняются.
- После этапа Windows и после этапа Android — ревью всей ветки отдельным агентом; замечания Critical/Important исправляются с тестом.
- Карты `obsidian/` обоих репозиториев обновляются в тех же коммитах.

## Выпуск

Только после ревью обоих этапов: Windows — 0.3.0 (тег `v0.3.0`, сборка установщика в CI, как у 0.2.x); Android — 0.2.0 (`versionCode 3`, тег `v0.2.0`, подписанный APK из CI). Порядок: сначала Windows-релиз, затем Android — баннер Android смотрит в свой репозиторий, Windows — в свой.
