# Claude VM GUI 0.2 — дизайн

Доработка приложения из спецификации `2026-10-18-claude-vm-gui-design.md`. Всё, что здесь не сказано, остаётся как в 0.1.x.

## Цель

Пять изменений по ТЗ пользователя:

1. Картинки и длинный многострочный текст (то, что Claude Code сворачивает в `[Image #N]` и `[Pasted text #N …]`) отправляются одним нажатием Enter, а не двумя.
2. Вход по паролю. Если пароль не задан, вход по SSH-ключу, как раньше.
3. Панель с параметрами ВМ: диск прогрессбарами, CPU графиком и т. д.
4. Когда в сессии запущен claude, вместо трансляции терминала показывается содержимое — лента переписки. Подсказки ввода, выбор ответа стрелками и прочая работа с консолью сохраняются. Когда claude не запущен, транслируется терминал, как сейчас.
5. Сессии: перетаскивание, закрепление (ПКМ → «Закрепить», булавка, закреплённые всегда выше), именованные группы (свернуть, развернуть, закрепить), страницы, если всё не помещается.

Правила ТЗ: дизайн в прежнем стиле; при неясностях — спрашивать; после кода — ревью отдельным агентом.

### Решения, принятые с пользователем

| Вопрос | Решение |
|---|---|
| Меню Claude Code в ленте | Карточка с вариантами; ↑↓/Enter/Esc/цифры уходят в claude, клик мышью тоже; нераспознанное — терминал на это время |
| Хранение пароля | В зашифрованном виде через Electron `safeStorage` (DPAPI) |
| Где параметры ВМ | Панель справа в главном окне, кнопка «Сервер» в сайдбаре |
| Какие параметры | CPU, RAM, swap, диски, сеть, топ процессов, сведения о системе |
| Отправка | Сначала подтвердить причину второго Enter, затем ждать готовности поля ввода |
| Сессии | Части 3 дизайна в чате приняты без изменений (ниже — раздел 5) |

Макет: артефакт «Claude VM — макет», ряд «v0.2» — `Feed`, `VmPanel`, `SessionMenu`.

## 1. Отправка одним Enter

**Гипотеза причины.** Сейчас `TerminalService.send` пишет вставку `ESC[200~…ESC[201~`, а через 30 мс — `\r`. Claude Code обрабатывает большую вставку и путь к картинке асинхронно (сворачивает в плейсхолдер, читает файл картинки). Enter, пришедший раньше, теряется. Перед исправлением гипотеза проверяется на настоящем claude (раздел «Проверка с настоящим claude»). Если причина другая, исправление меняется, а спецификация дополняется.

**Причина подтверждена** (2026-10-19, Claude Code 2.1.303, вставка через подключённый к tmux PTY, как в приложении). Если `\r` приходит в одном куске с концом вставки, Claude Code теряет Enter: путь к картинке превращается в `[Image #1]`, а сообщение остаётся в поле. Отдельная запись через 30 мс на localhost доходит отдельно и срабатывает. По сети с Windows пакеты склеиваются, и 30 мс не спасают.

**Исправление.** В `send` после проверки `checkWritable`:

1. Записать вставку без Enter.
2. Опрашивать экран (`capture-pane`, раз в 60 мс, не дольше 3 с). Поле ввода готово, когда его содержимое (`inputText(screen)`, см. ниже) не пустое и одинаково на двух опросах подряд.
3. Отправить `\r`.
4. Опрашивать до 1,5 с. Сообщение принято, если поле стало пустым или его содержимое изменилось.
5. Если поле не изменилось, отправить `\r` ещё раз (ровно один повтор) и опрашивать ещё 1,5 с.
6. Не изменилось и после повтора — ошибка `SEND_NOT_CONFIRMED`: «Claude Code не принял Enter. Посмотрите в терминал».

Если поле ввода на экране не распознаётся (`inputText` вернул `null`), отправка идёт по-старому, но с паузой 300 мс перед `\r`, без подтверждения.

Пока идёт отправка, в поле ввода приложения нельзя отправить второе сообщение (флаг `sending` уже есть).

`inputText(screen: string): string | null` — чистая функция в `src/shared/screen-parse.ts`. На вход идёт снимок `capture-pane -e` (с SGR-атрибутами). Возвращает текст поля ввода Claude Code или `null`, если поля нет:
- берутся строки между двумя линиями из `─` вокруг приглашения `❯`;
- само приглашение отбрасывается;
- строки склеиваются через `\n` и обрезаются по краям.

Пустое поле Claude Code показывает серой подсказкой (`❯ Try "…"`, атрибут dim). Текст с атрибутом dim в поле ввода не учитывается, поэтому пустое поле даёт `''`. Точный вид поля фиксируется по снимкам экрана настоящего claude (фикстуры).

## 2. Вход по паролю

**Конфигурация.** В `VmConfig` добавляется поле `hasPassword?: boolean`, только для чтения. Сам пароль в интерфейс не попадает никогда. В `config.json` хранится `passwordEnc` — base64 от `safeStorage.encryptString(password)`.

**IPC.** `config.save(c: VmConfig, password?: string | null)`:
- `undefined` — не трогать;
- `null` — удалить;
- строка — зашифровать и сохранить.

Если `safeStorage.isEncryptionAvailable()` ложно, сохранение пароля возвращает `CONFIG_INVALID` «Шифрование недоступно, пароль не сохранён».

**Настройки.**
- Поле «Пароль (необязательно)», `type="password"`.
- Если пароль сохранён, вместо поля показывается «Пароль сохранён» с кнопками «Изменить» и «Удалить».
- Поле ключа остаётся. Путь к ключу больше не обязателен, если задан пароль; если пароля нет, ключ обязателен, как раньше.

**SSH.** `authHandler` в `ssh2` перебирает методы по порядку:
1. ключ (если файл прочитался);
2. ssh-agent (если есть);
3. `password` (если пароль сохранён);
4. `keyboard-interactive`, где на каждый запрос с `echo: false` отвечаем паролем (если пароль сохранён).

Методы, которые сервер не предлагает, пропускаются. Ключ, который не читается, при сохранённом пароле — не ошибка.

**Ошибки** (`AUTH_FAILED`, текст зависит от причины):
- «Сервер не принял ни ключ, ни пароль»;
- «Сервер не принял ключ …» — как раньше, если пароля нет;
- «На сервере выключен вход по паролю» — пароль есть, но сервер не предлагает ни `password`, ни `keyboard-interactive`.

Пароль не пишется в логи и сообщения об ошибках. Проверка ключа сервера (known_hosts) не меняется.

## 3. Панель «Сервер»

**Открытие.** Кнопка «Сервер» внизу сайдбара, над «Настройки подключения», открывает панель шириной 400 px справа поверх основной колонки. Под панелью затемнение. Закрывается по ×, Esc и клику по затемнению. Фокус переходит в панель и возвращается на кнопку при закрытии.

**Сбор (`src/main/metrics.ts`, `MetricsService`).** Одна команда по SSH с разделителями:

```
cat /proc/stat; echo SEP; cat /proc/meminfo; echo SEP; cat /proc/loadavg /proc/uptime; echo SEP;
cat /proc/net/dev; echo SEP; df -PB1 -x tmpfs -x devtmpfs -x squashfs -x overlay -x efivarfs;
echo SEP; ps -eo pid=,ppid=,pcpu=,rss=,comm=,args= --sort=-pcpu | head -n 8
```

- Пока панель открыта, команда выполняется раз в 2 с; в фоне, пока есть подключение, — раз в 10 с. Хранятся последние 5 минут (150 точек).
- CPU% считается по разнице `/proc/stat` между двумя замерами. Сеть — по разнице байтов `/proc/net/dev` основного интерфейса: интерфейс с наибольшим трафиком, кроме `lo`.
- Сведения о системе запрашиваются один раз после подключения: `/etc/os-release` (PRETTY_NAME), `uname -r`, `nproc`, `claude --version` через `bash -lc`.
- Для процессов claude ищется имя tmux-сессии: по `~/.claude/sessions/<pid>.json` (поле `tmux`, см. раздел 4) или по родителю-панели.
- Ошибка замера не роняет панель: показывается последнее значение и подпись «нет данных N с».

**Разбор.** Чистые функции в `src/shared/metrics-parse.ts`: `parseCpu`, `cpuPercent(prev, next)`, `parseMem`, `parseLoad`, `parseUptime`, `parseNetDev`, `pickInterface`, `parseDf`, `parsePs`, `parseOsRelease`. Тесты — на фикстурах настоящего вывода Ubuntu.

**Вид** (макет `VmPanel`):
- **Сведения:** ядро, время работы, число ядер, версия Claude Code.
- **Процессор:** процент крупно, SVG-график за 5 минут, load average.
- **Память:** RAM прогрессбаром со значением «X из Y ГБ», swap — тонкий бар.
- **Диски:** бар на каждую точку монтирования. При 80 % и выше бар цвета `--accent-strong`, при 90 % и выше — `--danger`, подпись того же цвета.
- **Сеть:** ↓/↑ в секунду и график двух линий.
- **Процессы:** таблица топ-5 по CPU: имя (у claude — «· имя сессии»), CPU %, память.

Графики — собственный компонент `Sparkline` (SVG, без библиотек), прогрессбары — `role="progressbar"` с `aria-valuenow`. Числа — в русском формате (запятая, «ГБ», «МБ/с»).

## 4. Лента вместо терминала

### Источники данных

**Связь tmux-сессии с сессией Claude Code.**
- Claude Code пишет `~/.claude/sessions/<pid>.json` с полями `pid`, `sessionId`, `cwd`, `tmux` (вида `имя:@окно.%панель`), `status` (`idle`/`busy`), `version`.
- Приложение берёт `pane_pid` и его дочерние процессы и ищет файл, у которого `pid` — один из них. При запуске командой `claude` это сам `pane_pid`. Дополнительно сверяется поле `tmux` (оканчивается на `.<pane_id>`). Устаревшие файлы мёртвых процессов так не совпадут.
- `status` бывает `idle`, `busy` и `waiting` (ждёт ответа в меню); «работает» — это `busy`.
- Журнал лежит в `~/.claude/projects/<cwd, где / и . заменены на ->/<sessionId>.jsonl`.
- `sessionId` проверяется регуляркой UUID, путь собирается только из проверенных частей и экранируется `shellQuote`.
- Каталог `~/.claude` для тестов переопределяется переменной `CVG_CLAUDE_DIR`.

**Журнал.**
- `TranscriptService` (`src/main/transcript.ts`) при открытии сессии читает последние 1,5 МБ файла.
- Дальше следит за файлом: `tail -c +<offset> -F` в отдельном exec-канале. Новые строки разбираются и отправляются в интерфейс.
- Каждые 2 с (вместе с опросом экрана) перепроверяется связка pane → sessionId. Если id сменился (`/clear`, `/resume`), лента перезагружается.
- «Показать раньше» дочитывает предыдущие 1,5 МБ.

**Разбор журнала** — `parseTranscriptLines(lines, state) → ChatItem[]` в `src/shared/transcript-parse.ts`:

| Запись журнала | Элемент ленты |
|---|---|
| `type: user`, `message.content` — строка или `text`-блоки, без `isMeta` | `user`: текст; пути к картинкам из uploads и `[Image #N]` показываются чипами |
| `type: assistant`, блок `text` | `assistant`: markdown |
| `type: assistant`, блок `thinking` | `thinking`: свёрнут, с длительностью, если её можно вычислить по меткам времени |
| `type: assistant`, блок `tool_use` | `tool`: имя, краткое описание входа (`Bash` — команда, `Read`/`Write`/`Edit` — путь, `Grep` — шаблон, прочее — первое строковое поле), статус «выполняется» |
| `type: user`, блок `tool_result` | дополняет свой `tool` по `tool_use_id`: результат (текст, до 200 строк с «показать всё»), ошибка (`is_error`) |
| `isSidechain: true` | действия субагента, вложенные внутрь строки `Task`/`Agent` |
| остальные типы (`attachment`, `api-request*`, `mode`, `ai-title`, `file-history-*`, `system`, …) и неизвестные | пропускаются |

Строка, которая не разбирается как JSON, пропускается. Если подряд не разобрались 20 строк или файла нет, лента выключается: показывается терминал и баннер «Не удалось прочитать переписку — показан терминал».

**Экран.**
- `ScreenWatcher` (`src/main/screen.ts`), пока открыта сессия, раз в 500 мс делает один exec: `pane_current_command`, дочерние процессы, `capture-pane -p` (как `checkWritable`) и связку с `sessions/*.json`.
- Отдаёт `ScreenState`, её считает чистая функция `classifyScreen(screen) → ScreenState`:

```ts
type ScreenState =
  | { kind: 'no-claude' }                                    // в панели не claude
  | { kind: 'prompt'; status: string | null; input: string } // обычное поле ввода
  | { kind: 'menu'; menu: ParsedMenu }                       // распознанное меню
  | { kind: 'unknown' };                                     // всё прочее
interface ParsedMenu {
  title: string; context: string[];
  options: { n: number | null; label: string; description: string; selected: boolean }[];
  notes: string[]; hint: string | null;
}
```

- **Меню:** подсказка из `dialogOpen` и блок вариантов. Вариант по умолчанию отмечен `❯`, остальные выровнены по той же колонке.
  - Номера есть не всегда: в «доверять папке?» вариантов `No, exit` и `Yes, I trust this folder` без номеров, причём по умолчанию выбран `No, exit`.
  - Варианты могут переноситься на несколько строк. Тогда продолжение с бо́льшим отступом идёт в описание.
  - В `/model` описание отделено от названия двумя и более пробелами. Перед номером может стоять стрелка прокрутки `↓`.
  - Строки вроде `… +2 models` и `● High effort ←/→ to adjust` попадают в `notes`.
  - Заголовок — первая непустая строка после ближайшей сверху линии (`─` или `▔`) или от верха экрана. Контекст — следующие непустые строки до вариантов, не больше 6.
  - Клик по варианту без номера отправляет нужное число ↑/↓ от выделенного и Enter.
- **Статус:** строка спиннера Claude Code (символ из набора спиннера + текст + «(… · esc to interrupt)»). В ленте показывается текст и время, без «esc to interrupt».
- Форматы фиксируются фикстурами со снимков настоящего claude: обычное поле; работа со спиннером; запрос разрешения Bash; запрос на правку файла; «доверять папке?»; AskUserQuestion; выбор `/model`; `/config`, который должен дать `unknown`.

### Что показывает основная колонка

| Состояние | Вид |
|---|---|
| claude не запущен (`no-claude`) | Терминал, как в 0.1 |
| `prompt` или `menu`, журнал читается | Лента; при `menu` над полем ввода карточка меню |
| `unknown` | Терминал, пока состояние не сменится |
| Журнал не читается | Терминал и баннер |
| Пользователь выбрал «Терминал» в шапке | Терминал, пока не выберет «Лента» |

- Переключатель «Лента | Терминал» в шапке виден, только когда claude запущен. Выбор не запоминается между сессиями.
- `TerminalView` всегда смонтирован: лента его только прячет. PTY, размер, OSC 52 и автопереподключение работают как раньше. Размер PTY при скрытом терминале — последний подогнанный.

### Лента (`ChatView`)

Макет `Feed`.
- Сообщения пользователя — справа, фон `--hover`-подобный тёплый (новый токен `--bubble`).
- Ответы — markdown через `react-markdown` + `remark-gfm`, без `rehype-raw`, то есть сырой HTML не исполняется. Код — моноширинный блок без подсветки. Ссылки открываются через `shell.openExternal`, только `http:` и `https:`.
- Инструменты — строки в общей рамке. По клику раскрываются вход и результат. Иконка: ✓ (`--ok`), ✗ при ошибке (`--danger`), спиннер, пока нет результата.
- Размышления — свёрнутая строка.
- Внизу — строка статуса из `ScreenState.status`, глиняного цвета, пока claude работает.
- Автопрокрутка вниз, если пользователь уже внизу. Если пролистал вверх — кнопка «↓ Новые сообщения».
- В начале — «Показать раньше», если файл не прочитан целиком.

### Карточка меню (`MenuCard`)

- Заголовок, контекст (моноширинно, если похоже на команду или путь), варианты с номерами, подсказка по клавишам.
- Клавиши, пока карточка в фокусе (фокус ставится при появлении): ↑ ↓ ← → Enter Esc, цифры 1–9, Tab, Shift+Tab. Отправляются в PTY как есть (`\x1b[A`, `\x1b[B`, `\x1b[D`, `\x1b[C`, `\r`, `\x1b`, цифра, `\t`, `\x1b[Z`).
- Клик по варианту с номером отправляет его цифру. Без номера — нужное число ↑/↓ и Enter.
- Варианты, где Claude Code ждёт текст («Нет, и сказать, что делать иначе»), после выбора возвращают обычное поле ввода — дальше как обычное сообщение.
- Выделенный вариант и закрытие меню берутся из следующего опроса экрана, а не угадываются.

### Поле ввода

- Подсказки `/` и `@`, картинки, модель и effort — без изменений.
- При `menu` поле неактивно: «Сначала ответьте на вопрос выше».
- Пока статус «работает» (`sessions/*.json` → `busy` или есть строка спиннера), рядом с отправкой кнопка «Остановить · Esc». Она отправляет `\x1b`, только если состояние `prompt` (в меню Esc отвечает «отмена» — это делает карточка).

### IPC

Новые методы и события в `Api`:

```ts
chat: {
  onItems(cb: (e: { session: string; reset: boolean; items: ChatItem[]; hasEarlier: boolean }) => void): Unsubscribe;
  onScreen(cb: (e: { session: string; state: ScreenState; busy: boolean }) => void): Unsubscribe;
  onUnavailable(cb: (e: { session: string; reason: string }) => void): Unsubscribe;
  loadEarlier(): Promise<Result<void>>;
  key(k: MenuKey): Promise<Result<void>>; // 'up'|'down'|'left'|'right'|'enter'|'esc'|'tab'|'shift-tab'|'1'…'9'
};
metrics: {
  setActive(fast: boolean): void;              // панель открыта/закрыта
  onSample(cb: (s: MetricsSample) => void): Unsubscribe;
  info(): Promise<Result<SystemInfo>>;
};
layout: { get(): Promise<SidebarLayout>; save(l: SidebarLayout): Promise<Result<void>> };
links: { open(url: string): void };            // только http/https
```

- Лента и экран запускаются вместе с `term.open` и останавливаются при закрытии сессии или отключении.
- `chat.key` проверяет клавишу по белому списку и, как `send`, требует, чтобы на переднем плане был claude. Наличие меню не требуется: Esc и Shift+Tab нужны и в обычном поле.
- Новые коды ошибок: `SEND_NOT_CONFIRMED`, `NO_TRANSCRIPT`.

## 5. Сессии: порядок, закрепление, группы, страницы

**Модель** (`src/shared/layout.ts`, чистые функции):

```ts
interface SidebarLayout { v: 1; items: LayoutItem[] }
type LayoutItem =
  | { kind: 'session'; name: string; pinned?: boolean }
  | { kind: 'group'; id: string; name: string; pinned?: boolean; collapsed?: boolean; sessions: { name: string; pinned?: boolean }[] };
```

**Инвариант:** в каждом списке (верхний уровень, сессии группы) закреплённые идут раньше незакреплённых. Каждая сессия встречается не больше одного раза.

**Функции:**
- `reconcile(layout, tmuxNames)` — убирает исчезнувшие сессии, новые добавляет первыми среди незакреплённых верхнего уровня; пустые группы остаются.
- `move(layout, from, to)` — `to`: позиция в верхнем уровне или в группе. Если позиция нарушает инвариант, она прижимается к границе своей зоны.
- `togglePin`, `createGroup(name, withSession?)`, `renameGroup`, `deleteGroup` (сессии уходят на верхний уровень на место группы), `toggleCollapsed`, `moveToGroup`, `removeFromGroup`.
- `normalize` — восстанавливает инвариант после загрузки файла. Повреждённый файл — пустая раскладка.

Имя группы: 1–40 символов, обрезается по краям, дубликаты разрешены (у групп есть `id`).

**Хранение.**
- `layout.json` в папке данных приложения, объект `{ [host]: SidebarLayout }`. В репозиторий не попадает: это папка данных Windows.
- Сохранение — через `layout.save` после каждого изменения, с отложенной записью 300 мс в главном процессе.

**Сайдбар** (макеты `Feed`, `SessionMenu`):
- Разделы «Закреплённые» (если есть) и остальные, между ними тонкая линия.
- Заголовок группы: шеврон, имя, число сессий, булавка, если закреплена. Сессии группы — с отступом и линией слева.
- **Перетаскивание** — HTML5 drag-and-drop без библиотек:
  - во время перетаскивания линия `--accent` показывает место вставки;
  - сброс на заголовок группы кладёт сессию в группу; если группа свёрнута, сессия встаёт первой среди незакреплённых;
  - группы перетаскиваются только на верхнем уровне, группа в группу не вкладывается;
  - сброс в чужую зону закрепления прижимается к границе (`move`);
  - задержка курсора 600 мс над стрелкой пейджера перелистывает страницу.
- **ПКМ по сессии** (`ContextMenu`): Закрепить/Открепить · Переместить в группу ▸ (группы + «Новая группа…») · Убрать из группы (активно только в группе) · Завершить сессию (с прежним подтверждением).
- **ПКМ по группе:** Закрепить/Открепить · Свернуть/Развернуть · Переименовать… · Удалить группу (с подтверждением: «Сессии останутся»).
- Имя новой группы и переименование — небольшой диалог в стиле `NewSessionDialog`.
- **Клавиатура:**
  - меню открывается по Shift+F10 и клавише меню;
  - Alt+↑/↓ переставляет элемент в фокусе (по тем же правилам `move`);
  - в меню — стрелки, Enter, Esc.
- **Страницы.** `paginate(rows, rowHeights, available) → Page[]` в `src/shared/layout.ts`:
  - строки — плоский список (заголовок раздела, заголовок группы, сессия, разделитель) с высотами из констант, совпадающих с CSS;
  - `available` — высота списка (`ResizeObserver`);
  - если группа разорвана страницей, на следующей странице повторяется её заголовок с пометкой «продолжение»;
  - пейджер «‹ N / M ›» виден, только когда страниц больше одной;
  - при выборе сессии и при перелистывании во время перетаскивания показывается нужная страница.

## Внешний вид

- Без изменений стиля: токены из `tokens.css`, прежние шрифты и радиусы.
- Новые токены: `--bubble` (светлая тема `#F0EEE6`, тёмная `#3a3a37`) и `--chart` (= `--accent-strong`).
- Новые иконки (булавка, шеврон, папка, пульс) — в `icons.tsx`, тем же stroke-стилем.
- Тёмная тема и ширина окна от 960 px работают.

## Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Enter не принят после повтора | `SEND_NOT_CONFIRMED`, текст сообщения остаётся в поле приложения |
| Журнал не найден / не разбирается | Терминал + баннер, повторная попытка при следующей смене `sessionId` или переоткрытии сессии |
| Экран не распознан | Терминал до смены состояния |
| Замер метрик не удался | Последние значения + «нет данных N с» |
| Обрыв связи | Как в 0.1; лента, экран и метрики перезапускаются после `reattached` |
| `layout.json` повреждён | Пустая раскладка, файл перезаписывается при первом изменении |
| `safeStorage` недоступен | Пароль не сохраняется, понятное сообщение |

## Безопасность

- Пароль: только в главном процессе, только в зашифрованном виде на диске, не в логах и не в IPC к интерфейсу.
- Пути на ВМ (журнал, `sessions`) собираются из проверенных частей (UUID, имя файла `<pid>.json`), экранируются.
- `chat.key` — белый список клавиш, отправка только при claude на переднем плане.
- Markdown без сырого HTML. Ссылки — только `http:`/`https:` через `shell.openExternal`, навигация окна по-прежнему запрещена.
- CSP не ослабляется: `react-markdown` не требует `unsafe-eval`.
- Адрес ВМ по-прежнему не попадает в репозиторий; фикстуры журналов и экранов очищаются от адреса, путей пользователя и содержимого переписки (переписка в фикстурах — синтетическая).

## Тестирование

- **Unit (vitest)** на чистые функции:
  - `inputText`, `classifyScreen` — фикстуры экранов;
  - `parseTranscriptLines` — синтетический журнал по форме настоящего;
  - функции `metrics-parse`;
  - `layout` (`reconcile`, `move`, инвариант, `paginate`);
  - помощники пароля в конфигурации.
- **Интеграция:**
  - вход по паролю и keyboard-interactive — на тестовом SSH-сервере `ssh2.Server` внутри теста, без изменений системы;
  - `TranscriptService` и `ScreenWatcher` — на localhost с `CVG_CLAUDE_DIR` во временной папке и фейковым claude;
  - `MetricsService` — на localhost;
  - отправка с подтверждением — фейковый claude, который рисует поле ввода, принимает вставку с задержкой и «теряет» ранний Enter (воспроизводит баг).
- **E2E (Playwright `_electron`):**
  - лента с фейковым журналом;
  - карточка меню и ответ стрелками;
  - переключатель «Лента | Терминал»;
  - панель «Сервер»;
  - закрепление, группа, перетаскивание, страницы при маленьком окне;
  - пароль в настройках.
- **Проверка с настоящим claude** в сессии `cvg-test-*` с `ANTHROPIC_BASE_URL=http://127.0.0.1:9` (закрытый порт — запросов к модели нет):
  - причина второго Enter и исправление: большая вставка, картинка;
  - снимки экранов для фикстур: «доверять папке?» в новой папке, меню `/model`, `/config`;
  - настоящий журнал после отправки.
- Все прежние тесты остаются зелёными. Тесты трогают только tmux-сессии `cvg-test-*`.
